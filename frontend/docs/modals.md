# Parallel routing for modals

[Оффициальная документация Next.js](https://nextjs.org/docs/app/api-reference/file-conventions/parallel-routes#modals)

## Архитектурное расположение

Так как роутинг для модалок параллельный, соответственно и маршруты у них отделены в своей папке: `@modals`

Допустим нам надо отобразить модалку при нажатии на кнопку войти на странице `/auth` по адресу `/auth/login`

Вот как это выглядит в архитектуре:

```
|(@modals) // Верхнеуровневая папка для роутинга модалок. У нас она будет единственная в проекте, чтобы не раздувать папок на каждый слой
|--(auth)
|----(.login) // называем часть маршрута через `.`, чтобы при обновлении страницы у нас была не голая модалка, а страница-фолбэк
|------page.tsx
|(auth)
|--page.tsx
|--(login)
|----page.tsx // Страница-фолбэк, т.к. мы перехватываем этот маршрут модалкой, то эта страница отобразиться только если мы перейдём по прямой ссылке
```

## Использование модалок (пошаговая инструкция)

1. Создаём роут(папку) для модалки в папке `@modals` и `page.tsx`, где возвращается модалка

```tsx
// app/@modals/auth/.login/page.tsx
import { Modal } from '@/app/shared/ui';

export default function LoginModal() {
    return (
      <Modal title="Вход">
        { // Форма входа }
      </Modal>
    );
}
```

2. Создаём страницу-фолбэк, которая будет открываться по прямой ссылке на модалку. При необходимости добваляем элементы управления

```tsx
// app/auth/login/page.tsx
export default function Page() {
  return (
    <>
      { // Доп UI элементы управлления - если надо }
      { // Форма входа }
    </>
  )
}
```
